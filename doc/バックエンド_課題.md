- ユーザー管理

- 商品の出品
- 商品の購入

## ユースケース

### ユーザー管理

- ユーザーはメールアドレスとパスワードでアカウントを作成できる。
- ログイン後はユーザー情報を編集可能。
  - ユーザー名
  - メールアドレス
  - パスワード
  - 電話番号
  - 住所(商品の発送先)
  - 自己紹介文
- ユーザーは出品者にも購入者にもなれる。

### 商品の検索

- 商品は以下の条件で検索できる。
  - カテゴリ
  - キーワード
  - 価格帯
  - 出品者の評価
- `出品中(LISTED)`状態の商品のみ検索できる。

### 商品の出品

- 出品時に以下の情報を入力する。
  - タイトル
  - 説明
  - 価格
  - 商品の状態(新品／中古など)
  - カテゴリ(例: ファッション > バッグ > リュック)
    - カテゴリは商品に対して1つだけ設定できる
    - カテゴリは階層化されている
    - 階ーは何階層でも定義できるようにする
  - タグ(例: 「アウトドア」「メンズ」)
    - タグは商品に対して複数設定できる
  - 商品画像
    - 画像は商品に対して複数設定できる
- 出品後は`出品中(LISTED)`状態になる。
- 出品者は`出品中(LISTED)`状態の出品を取り消す(削除する)ことができる。

### 商品の購入

- 購入者は出品中の商品に対して、購入申し込みができる。
- 購入が確定すると`取引中(RESERVED)`状態になり、支払いを行う。

### 支払・発送

- 支払いが完了すると`発送待ち(PAID)`状態になる。
- 出品者が発送情報(追跡番号など)を登録すると`発送済み(SHIPPED)`になる。
- 購入者が受取を確認すると`受取済み(DELIVERED)`になり、評価投稿が可能になる。
- 双方が評価を投稿すると`取引完了(COMPLETED)`になる。

### 評価

- 取引ごとに、購入者・出品者が互いを評価(1〜5の星＋コメント)できる。

### 支払・売上管理

- 支払履歴を確認できる。
- 商品が`受取済み(DELIVERED)`になると、出品者に売上金が発生する。
- 商品の価格から10%の手数料が引かれた金額が売上金となる。
- 売上金は任意のタイミングで銀行振込の申請ができる。

### お気に入り

- ユーザーは商品をお気に入りに追加・削除できる。
- ユーザーは自分が登録したお気に入り商品を確認できる。
- 商品ごとにお気に入り登録数を確認できる。

### 出品に対するコメント

- ユーザーは商品に対してコメントを投稿できる。
- 出品者やユーザーはコメントに対して返答できる。

### 通知

- 以下のイベントで通知が送られる。
  - 商品が購入されたとき
  - 発送されたとき
  - 評価されたとき
  - 不適切な商品通報により、商品が警告・削除されたとき
- ユーザーは自分に対して送られた通知を確認できる。
- ユーザーは各通知が既読済みかどうか確認できる。

### 通報

- ユーザーは不適切な商品や、コメントを通報できる。
- 管理者は報告を確認し、「警告」や「削除」などの対応を記録する。
- 不適切な商品は商品の一覧から除外される。
- 一定回数違反を繰り替えしたユーザーは利用が停止される。

## 課題詳細

### DB

- PostgreSQLを使用する。
- 以下の機能、ユースケースを実現するために必要なテーブルを設計する。
  - ユーザー管理
  - 商品の検索
  - 商品の出品
  - 商品の購入
  - 支払・発送
  - 評価
- 余力があれば他の機能・ユースケースを実現するために必要なテーブルを設計する。

#### 成果物

- DDLファイル
- ER図
  - ER図はMermaid、PlantUML、Draw.ioなどテキストベースで管理できる形式を使用して作成する。

### API

- 使用ソフト・OSS
  - Node.jsを使用する。
  - バックエンドフレームワークを使用する場合はExpress, NestJS, Honoから選択する。
  - ORMを使用する場合はSequelize, Prisma, TypeORMから選択する。
- 以下の機能、ユースケースを実現するために必要なREST APIを設計実装する。
  - ユーザー管理
  - 商品の検索
  - 商品の出品
- 設計時の注意
  - 今後の機能拡張に耐えられる適切なAPI設計(メソッド・パス)にする。
  - リクエスト・レスポンスボディ・クエリパラメータ・パスパラメータはユースケースから読み解いて設計する。
- 実装時の注意
  - 決裁関連の処理は実装は困難なため、ダミーの処理で代替する。
  - 画像アップロードの実装はストレージが存在しないため、ダミーの処理で代替する。

#### 成果物

- API仕様書
  - Open API形式のyamlファイル
- ソースコード
- DBと合わせてローカルPC内で動作できる環境(提出不要)
